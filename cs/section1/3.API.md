# API

## 1. API란?

**API(Application Programming Interface)**는 둘 이상의 컴퓨터 프로그램이 서로 통신할 수 있도록 제공되는 **인터페이스이자 통신 규칙의 집합**이다.

API에는 일반적으로 다음과 같은 내용이 정의되어 있다.

- 요청을 보낼 주소인 엔드포인트
- 통신 방식과 프로토콜
- HTTP 메서드
- 요청 및 응답 데이터 형식
- 인증 방식
- 오류 코드

즉, API는 프로그램 사이에서 요청과 응답을 주고받기 위한 **중계 계층**이라고 볼 수 있다.

> 일반적으로 API라고 말할 때는 HTTP를 기반으로 통신하는 **웹 API(Web API)**를 의미하는 경우가 많다.

---

## 2. Interface

**인터페이스(Interface)**는 서로 다른 두 개의 시스템이나 장치가 정보 또는 신호를 주고받는 **접점이나 경계면**이다.

사용자는 상대 시스템의 내부 구현 방식을 알지 못하더라도, 외부에 공개된 인터페이스의 사용 방법만 알면 해당 시스템을 사용할 수 있다.

예를 들어 클라이언트는 서버 내부에서 어떤 프로그래밍 언어를 사용하는지, 데이터베이스가 어떻게 설계되어 있는지 알 필요가 없다. 서버가 제공하는 API 명세에 맞게 요청을 보내면 필요한 기능을 사용할 수 있다.

---

## 3. API의 장점

### 3.1 내부 구현을 숨길 수 있다

API 제공자는 서비스의 중요한 내부 정보를 외부에 직접 공개하지 않아도 된다.

예시는 다음과 같다.

- 데이터베이스 설계 구조
- 데이터베이스 테이블 정보
- 서버 내부 로직
- 서버에서 사용하는 상수값
- 내부 시스템 구성

이를 통해 서비스의 **보안성과 캡슐화**를 높일 수 있다.

### 3.2 사용자가 내부 구현을 알 필요가 없다

API 사용자는 서비스가 내부적으로 어떻게 구현되어 있는지 알 필요 없이, API 명세에 맞게 요청을 보내고 필요한 응답을 받을 수 있다.

예를 들어 날씨 API를 사용하는 개발자는 기상 데이터가 어떤 방식으로 수집되고 저장되는지 알지 못하더라도 날씨 정보를 사용할 수 있다.

### 3.3 개발 시간과 비용을 줄일 수 있다

Open API를 활용하면 이미 구현된 기능이나 데이터를 다시 개발하지 않아도 된다.

예시는 다음과 같다.

- 지도 API
- 결제 API
- 소셜 로그인 API
- 공공데이터 API
- 번역 API

이를 통해 애플리케이션 개발 과정을 단순화하고 개발 시간과 비용을 절약할 수 있다.

### 3.4 내부 변경의 영향을 줄일 수 있다

서버 내부의 데이터베이스 구조나 비즈니스 로직이 변경되더라도 외부에 제공되는 API의 요청 및 응답 형식을 유지하면 클라이언트는 기존 방식대로 API를 사용할 수 있다.

즉, API는 클라이언트와 서버를 분리하여 내부 구현 변경이 외부 사용자에게 미치는 영향을 줄여준다.

다만 API의 요청 또는 응답 형식 자체가 변경되면 클라이언트 코드도 수정해야 할 수 있으므로, 하위 호환성 유지와 API 버전 관리가 중요하다.

### 3.5 요청과 데이터를 한곳에서 관리할 수 있다

API 제공자는 특정 기능과 관련된 요청을 하나의 API에서 통합적으로 처리할 수 있다.

예를 들어 사용자가 특정 버튼을 클릭한 기록이 필요하다면 해당 API 요청이 발생할 때 다음과 같은 처리를 함께 수행할 수 있다.

- 클릭 이벤트 기록
- 사용자 행동 분석
- 접근 권한 검사
- 요청 로그 저장
- 오류 추적

이를 통해 서비스의 요청 흐름과 데이터를 일관되게 관리할 수 있다.

## 4. API의 종류

### 4.1 Private API

Private API는 기업이나 조직의 내부 시스템에서 사용하는 API이다.

주로 다음과 같은 상황에서 사용된다.

- 사내 서비스 간 통신
- 서버와 서버 간 통신
- 내부 마이크로서비스 간 통신
- 제한된 비즈니스 파트너와의 통신

외부 사용자가 자유롭게 접근할 수 없으며, 일반적으로 다음과 같은 인증 및 접근 제어 방식을 사용한다.

- API Key
- Access Token
- OAuth
- JWT
- IP 접근 제한
- 사설 네트워크

> API Key나 비밀키를 소스 코드에 직접 하드코딩하면 보안상 위험하므로 환경 변수나 별도의 보안 저장소를 사용하는 것이 좋다.

### 4.2 Public API

Public API는 외부 개발자나 일반 사용자에게 공개된 API이다.

누구나 사용할 수 있는 경우도 있지만, 대부분 회원가입이나 인증키 발급이 필요하다.

과도한 요청과 서버 부하를 방지하기 위해 다음과 같은 제한을 적용할 수 있다.

- 하루 요청 횟수 제한
- 분당 요청 횟수 제한
- 계정별 요청 제한
- API Key별 요청 제한
- 유료 요금제별 사용량 제한

이를 **Rate Limit**, 즉 요청 횟수 제한이라고 한다.

---

## 5. 정리

API는 서로 다른 프로그램이 정해진 규칙에 따라 기능과 데이터를 주고받을 수 있도록 만든 인터페이스이다.

API를 사용하면 서버의 내부 구현을 숨길 수 있고, 클라이언트는 내부 구조를 알지 못해도 필요한 기능을 사용할 수 있다. 또한 시스템 간 결합도를 낮추고, 기존 기능을 재사용하여 개발 시간과 비용을 줄일 수 있다.
